Classify → Plan → Execute

The four shapes of data

Everything above is glue around four small, frozen dataclasses defined once in models.py and passed between modules unchanged:

  • Category — an enum of the 15 output buckets (DRUMS, BASS, VOX, … OTHER).
  • ClassifiedFile — one source path plus the Category it matched (and which keyword did it).
  • PlannedAction — a source path, a destination path, and a category. This is what planner.py hands to everything downstream.
  • RunReport — the summary (total_files, copied_files, dry_run) handed back up to the caller once a run finishes.

Notice classification (ClassifiedFile) and planning (PlannedAction) are separate types. planner.py calls the classifier internally and folds the result straight into a PlannedAction — ClassifiedFile on its own is only really used inside classifier.py and its tests.

Walking the actual call order

cli.py:main() is the clearest place to see the wiring, in order: 

args = parser.parse_args(argv)

if config_path:                       # config.py
    overrides = load_keyword_overrides(config_path)
    keywords = build_effective_keywords(defaults=CATEGORY_KEYWORDS, overrides=overrides)

actions = plan_organisation(          # planner.py — classifies every file, returns PlannedAction[]
    source_dir, output_root, keywords=keywords, recursive=recursive, numbered=numbered
)

# ...print previews (--summary-only / --show-other) here...

if review:
    actions = review_actions(actions) # reviewer.py — only touches Category.OTHER items

report = execute_plan(actions, dry_run=dry_run, move=move)   # organiser.py

Two things worth internalising: classification happens once, inside plan_organisation — there's no separate "classify" pass you'll find yourself hunting for. And review only ever sees OTHER — anything already matched to a real category skips reviewer.py entirely and goes straight through.

Config detour: --config doesn't replace the built-in keyword table in classifier.py — build_effective_keywords (in config.py) merges the JSON file's keywords on top of CATEGORY_KEYWORDS, per category. The file only ever needs to contain the extra words you want to add.
